# Общий лейаут платформы

`PlatformLayout` размещает навигацию, рабочую область и опциональную боковую панель. В моках четыре продукта, а формы справа собраны из `TextInput`, `Select`, `DatepickerInterval` и `Checkbox`. Внутренние данные форм локальны. Штатные кнопки, типографика и поверхности приходят из UI Kit.

## Подключение нового продукта

1. Перенесите `src/PlatformLayout` в общую библиотеку монорепозитория и используйте существующие тему и публичные импорты UI Kit. Папка `dev/` нужна отдельной демонстрационной сборке.
2. Подключите каркас на уровне маршрута. Передайте общую навигацию платформы через `navigation.render`, а состояние активного продукта берите из роутера. Для щита, кнопки раскрытия и кнопки закрытия передайте готовые `Icon` из вашего реестра.
3. В `title` передайте заголовок. Действия, в том числе «Назад» и «Создать», идут в `actions`, инструменты над реестром — в `toolbar`, сам экран — в `children`.
4. Если продукту нужна боковая панель, передайте `rightPanel` с содержимым, `isOpen` и `onOpenChange`. Добавьте `trigger` для штатной кнопки в шапке. Если панель открывается из другого элемента продукта, передайте свой триггер и управляйте тем же состоянием.
5. Проверьте экран при 1440×900 и 1920×1080. Если страница уже под общей шапкой приложения, задайте `--platform-layout-height: 100%` на лейауте и определённую высоту его родителю. Левый список, основная область и содержимое правой панели прокручиваются независимо.

```tsx
<PlatformLayout
  title={productName}
  navigation={platformNavigation}
  actions={<ProductActions />}
  toolbar={<RegistryToolbar />}
  rightPanel={filtersAvailable ? {
    title: 'Фильтры',
    trigger: { label: 'Фильтры', icon: filterIcon },
    closeIcon,
    content: <ProductFilters />,
    isOpen: filtersOpen,
    onOpenChange: setFiltersOpen,
  } : undefined}
>
  <ProductScreen />
</PlatformLayout>
```

Навигация меняет ширину между 228 и 62 px. Правая поверхность появляется под шапкой, а центр плавно меняет ширину. Применяется `prefers-reduced-motion`. При закрытии штатной кнопкой или Escape фокус возвращается к штатному триггеру панели.

## Перенос с LayoutPlus

| В LayoutPlus | В новом каркасе |
| --- | --- |
| `navBar` и `onBackClick` | Заголовок в `title`. Готовый контрол «Назад» с прежним обработчиком в `actions` |
| `AreaLeft`, `areaLeftHeader` и `searchApi` | Контент реестра в `children`. Поиск и сортировка в `toolbar` или внутри продукта |
| `sidebar` и `onCreate` | Общая навигация в `navigation.render`. Создание в `actions` |
| `AreaRight` | Сначала проверьте назначение. Фильтры и вспомогательные настройки идут в `rightPanel`. Основная карточка остаётся в контенте продукта или на отдельном маршруте |
| `stage`, `isFullScreen`, сжатие на 1440 px, `isFlushBottom` | Режим списка и карточки выбирает продукт. Лейаут управляет геометрией и собственной прокруткой |

Для миграции сначала найдите вызовы `LayoutPlus` в продукте и проверьте, что лежит в `AreaRight`. Пилот можно подключить на отдельном маршруте или под флагом. После замены обёртки проверьте открытие и закрытие карточки, переход «Назад», сохранение выбора строки и фильтров, возврат прокрутки, вычисление размеров виртуализированной таблицы и видимый фокус.

| Сценарий | Оценка для одного разработчика |
| --- | --- |
| Новый продукт с готовым экраном | 2–4 часа на подключение, до 1 рабочего дня вместе с проверкой |
| Существующий простой список | 1–2 рабочих дня |
| Реестр с `MAIN/SECONDARY`, мастер-деталью и своей прокруткой | 2–4 рабочих дня |

Это предварительная оценка по архиву `LayoutPlus`. Для точной оценки нужно увидеть точки подключения и правила навигации конкретного продукта. Реализация таблиц, карточек, фильтрации и API оценивается отдельно.

## Storybook и HTML

Требуется Node.js 22 или новее. Распакуйте предоставленный архив в `local-ui-kit/`, чтобы появился путь `local-ui-kit/ui-kit/src`.

```bash
unzip /path/to/ui-kit.zip -d local-ui-kit
npm ci
npm run lint
npm run storybook
npm run build:storybook
```

Storybook запускается на порту 6006. После сборки откройте `storybook-static/layout-preview.html` для просмотра без интерфейса Storybook. Команда `npm run build:preview` отдельно собирает `preview-static/index.html`.

В автономной сборке настоящие компоненты берутся из неизменённого архива. В архиве отсутствует библиотека `@frontend/icon`, поэтому только в автономном режиме используется демонстрационный реестр иконок из `dev/iconPreview.tsx`. В монорепозитории используйте настоящий `@frontend/icon` и передавайте иконки щита и фильтра из него. Команда `npm run typecheck` в изолированной сборке также проверяет исходники архива и может обнаруживать ошибки в его типах, в том числе в сигнатурах refs и перегрузках `useBoolean`.

Собранное превью включает код и шрифты UI Kit. Храните сборку в разрешённом закрытом окружении.
